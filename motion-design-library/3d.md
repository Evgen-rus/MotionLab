# 3D

Рецепты 30–36 описывают адаптацию конкретных эффектов. Для готовой камеры и корпуса с экраном используйте [исполняемый модуль продуктовой сцены](commercial-shots.md). Общие функции и ограничения — в [README](README.md).

## Порядок работы в MotionLab

1. Выбрать конкретный 3D-кадр и то, что в нём должен увидеть зритель. Показать референс и реальный кадр из Three.js в обычных вариантах оформления. Для выбранного облёта взять два ракурса в существующей раскадровке.
2. Для нового 3D-кадра взять фиксированную версию Three.js, например `npm pack three@0.187.0 --ignore-scripts`, во временной папке проекта. Скопировать `build/three.module.js` и его `build/three.core.js` в `vendor/three/` внутри папки HTML-сцены вместе с `LICENSE`. Подключить `./vendor/three/three.module.js` в модуле сцены. Если дополнения импортируют `three` по имени, добавить локальный import map перед модульным скриптом. Нужные дополнения, геометрию, текстуры и шрифты хранить рядом со сценой с их лицензиями. Для собственных форм подойдут примитивы, `ExtrudeGeometry` или процедурная геометрия. Обычные титры, карточки и переходы оставить в HTML/CSS/SVG.
3. Создать камеру, свет и объекты один раз, дождаться готовности ассетов перед первым кадром. В `window.__video.seek(t)` вычислять из абсолютного времени в секундах положения, повороты, свет, видимость и состояние HTML-слоёв. Для каждого вызова выставлять значения целиком и завершать его `renderer.render(scene, camera)`. Не накапливать шаги движения, не читать wall-clock и не запускать самостоятельный цикл рендера. Источник в кадрах 60 FPS переводить в секунды независимо от FPS экспорта.
4. Проверить WebGL и титры в Workbench → «Структура сцены», несколько раз перемотать вперёд и назад. В штатном `render.mjs --stills` запросить, например, `0.4,1.2,0.4` в пределах длины сцены. Одинаковое время должно дать одинаковый PNG при одинаковых параметрах рендера, а второй ракурс должен отличаться. Для готового ролика использовать обычный `render.mjs --job` после утверждения раскадровки.

В предпросмотре Workbench `fetch` заблокирован политикой `connect-src 'none'`, в том числе для локальных файлов. Для модели из файла подготовить нужную геометрию в локальном JS-модуле и текстуры в локальных изображениях. Например, экспортировать данные геометрии из модуля и передать в `BufferGeometryLoader.parse()`.

## 30. Cube-Grid Ripple

**Результат:** Волна сетки кубов. **Когда:** объёмный фон.

**Пример MotionLab:** Объёмный фон в авторской HTML-сцене; вычислить следующий рецепт внутри `seek(t)`, привязав `dt=t-start` к началу элемента.

**Алгоритм / JS-псевдокод:**

```js
InstancedMesh 24x24; z=sum(kicks.filter(k<=t).map(k=>A*exp(-8*(r-speed*(t-k))**2)*exp(-(t-k)))); updateMatrix каждого экземпляра, needsUpdate=true
```

**Параметры и тайминг источника:** An InstancedMesh cube field (about 576 instances). Each kick spawns a radial ring that pushes the cubes in Z.

**Совместимость и зависимости:** Локальный Three.js (не установлен библиотекой), WebGL; для текста TextGeometry + FontLoader и локальный лицензированный font JSON. Доступность проверить перед применением. Все состояния вычислять из t; значения кадра источника делить на 60, а не на fps экспорта. Для 3D вручную вызвать renderer.render(scene,camera) в seek.

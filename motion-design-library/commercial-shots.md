# Постановка продуктовых и объясняющих сцен

Выберите одно действие, которое зритель должен увидеть. Для интерфейса покажите его контекст, приблизьте нужную деталь и дайте прочитать результат. Для объясняющего ролика можно показать путь сигнала или изменение состояния. Для имиджевого ролика можно связать объёмный объект и финальный титр формой или направлением движения. Эти идеи дают разные ключевые кадры для штатных вариантов оформления. В новом брифе коротко объясните, что изменится на экране и какой кадр покажет смысл каждого варианта.

## Приёмы

Скопируйте нужные модули рядом с HTML сцены. Время в секундах, экранные координаты в пикселях от левого верхнего угла кадра. Каждый `seek(t)` заново выставляет видимость, положение и стиль для всех использованных слоёв. События удобно назвать по действию (`suggestionReady`, `followUpSaved`). Привязывайте к ним и графику, и звук.

| Что показать | Модуль и параметры | Когда применять |
|---|---|---|
| 3D-устройство с читаемым экраном | `productStage(THREE, {width,height,canvas,finish})`, `cameraRig(camera, poses)` и `orbitPose(at,{azimuth,elevation,distance,target,fov})` в [product-stage.mjs](product-stage.mjs) | Покажите материал и скругления в наклонном ракурсе. Для интерфейса замедлитесь на фронтальной позе. Две одинаковые позы в разные моменты создают паузу. |
| Подлёт к интерфейсу | `focusView(t,{start,arrive,leave,end,target,anchor,zoom})` | Укажите, какую точку интерфейса перенести к какой точке кадра. `start…arrive` — подлёт, `arrive…leave` — чтение, `leave…end` — возврат. Применяйте `transform` с началом в `0 0`. |
| Карточка выходит из экрана | `liftCard(t,{start,end,from,to,arc})` и `placeRect(el,rect)` | Используйте один текст и стиль у экранного и вышедшего объекта. Для 3D можно проецировать точки экрана через `screenPosition(THREE,surface,camera,[u,v],size)`. Затормозите камеру в момент отделения, если геометрия карты должна точно совпасть. |
| Появление смысловыми группами | `revealGroups(elements,t,{starts,duration,distance})` | Сначала дайте контекст, затем действие или результат. Задавайте время для каждой смысловой группы и держите итоговое состояние. |
| Линия между сценами | `lineCarry(svgPath, marker,{start,cut,end})` возвращает функцию от `t` | Разместите общую линию поверх обеих сцен. Двигайте маркер по длине пути и держите фон в общей системе координат. |
| Совмещение объекта на склейке | `matchCut(t,{cut,incomingStart,outgoingEnd,rect,velocity})` | Сохраните общую рамку объекта и направление по обе стороны `cut`. У каждой сцены свои локальные часы `localTime`. Сверьте два соседних кадра склейки. |
| Волна записанной речи | `voiceLevels(t,envelope,{count,spacing,gain})` | Стройте волну из RMS фактического голосового стема. Показывайте нужную фразу в соответствующем интервале. |
| Интерфейс переходит в бренд-финал | `brandMorph(t,{start,end,from,to,radiusFrom,radiusTo})` | Сохраните общую форму при изменении размера и положения. Переключите текст по `uiOpacity` и `brandOpacity` и оставьте финал для чтения. |

Кроме 3D, функции находятся в [shot-motion.mjs](shot-motion.mjs). `from`, `to` и `rect` используют `{x,y,width,height}`. Подбирайте геометрию отдельно для широкого и вертикального форматов. Например, в узком кадре выносите пояснение под интерфейс. Дальняя перспектива и глубина резкости подходят для корпуса, а читаемый текст удобно оставить в 2D. Three.js и его лицензия остаются локальными и фиксированной версии. `productStage` принимает canvas с уже отрисованным интерфейсом. После его изменения поставьте `screen.needsUpdate = true`. Перед `screenPosition` обновите `camera.updateMatrixWorld()`.

## Пример использования

```js
import {focusView, liftCard, placeRect, revealGroups} from './shot-motion.mjs';

const cues = {detail: 1, reading: 2, lift: 4, liftDone: 4.7, context: 5};
function seek(t) {
  panel.style.transform = focusView(t, {
    start: cues.detail, arrive: cues.reading, leave: cues.lift, end: cues.liftDone,
    target: [350, 210], anchor: [420, 220], zoom: 1.25,
  }).transform;
  const pose = liftCard(t, {
    start: cues.lift, end: cues.liftDone,
    from: {x: 320, y: 180, width: 230, height: 120},
    to: {x: 90, y: 90, width: 320, height: 166},
  });
  placeRect(card, pose.rect);
  card.hidden = t < cues.lift;
  revealGroups(captions, t, {starts: [cues.liftDone, cues.context]});
}
```

Добавьте `data-element-id` и соответствующие интервалы для Workbench. Используйте существующее превью, чтобы проверить кадр при подлёте, чтении, перед склейкой и сразу после. Проверьте экспортируемый размер, минимальный кегль, читаемость русских «Ё», «Й» и окончания фраз, а также повторный кадр после произвольного перехода по времени.

## Запускаемые примеры и проверка

[Широкий «Сигнал»](shots-landscape.html) и [вертикальный «Сигнал»](shots-portrait.html) используют один исходник на русском. Подлёт виден в 1,7 с, отделение карточки — 3,1–4,15 с, линия идёт через склейку в 5,5 с, далее появляются группы, а финальный знак готов в 8,35 с. Подпись «Учебная кривая без аудио» обозначает синтетические значения для интерфейса демо. Реальную огибающую получайте из речи, как описано ниже.

```powershell
node .agents/skills/motionlab/scripts/render.mjs --in motion-design-library/shots-portrait.html --out "projects/Приёмы постановки/портрет-01" --stills 1.7,4.8,1.7,5.458,5.542,9.2 --qa yes
```

Для широкого кадра замените вход на `shots-landscape.html` и используйте новый каталог. Кадры 1 и 3 должны совпасть. Если стили текста различаются только во время подлёта и после обратной перемотки, проверьте, остаётся ли его панель в одном слое растрирования. В примере слой фиксирует `.panel {will-change: transform}`.

Для 3D-устройства подключите локальные модули Three.js с лицензией по [инструкции для 3D](3d.md). Передайте в `productStage` canvas с интерфейсом, затем отрисовывайте `stage.scene` после обновления камеры в каждом `seek(t)`. Если нужен внешний объект, используйте [подбор и проверку SimReady и GLB](../.agents/skills/motionlab/SKILL.md#optional-simready-references-and-models). Использованные подходы и версии см. в [источниках](commercial-shot-sources.md).

## Звук по меткам сцены

Сначала подготовьте музыку и отдельные эффекты штатным локальным music-production. В JSON плана храните длительность, времена событий в секундах и ссылки на файлы относительно плана. Минимальный пример с голосом:

```json
{
  "duration": 12.5,
  "events": {"voiceStarts": 0.7, "cardArrives": 6.4, "brand": 10},
  "music": {"file": "music/master.wav", "gain": 0.25},
  "narration": {"file": "voice.wav", "event": "voiceStarts", "gain": 0.8},
  "effects": [
    {"file": "swoosh.wav", "event": "cardArrives", "anchor": "peak", "gain": 0.4},
    {"file": "bell.wav", "event": "brand", "anchor": "end", "gain": 0.3}
  ]
}
```

```powershell
node motion-design-library/audio-cues.mjs mix --plan "projects/Название/звук/plan.json" --out "projects/Название/звук/микс-01"
node motion-design-library/audio-cues.mjs envelope --in "projects/Название/звук/микс-01/narration.wav" --out "projects/Название/звук/волна-01"
```

`start` совпадает с началом файла, `peak` с серединой самого громкого 20-мс интервала по RMS, `end` — с концом файла. Перепроверьте, что эти точки соответствуют слышимому действию. Микшер сообщает сдвиги в сэмплах, сохраняет `mix.wav` для `render --audio`, `narration.wav` для `check-audio.mjs` и `events.mjs` для локального импорта в сцену. Копируйте `events.mjs` и `speech-envelope.mjs` рядом с HTML. При огибающей из выровненного стема подавайте в `voiceLevels` абсолютное время `t`. Для нескольких реплик сначала соберите монтаж голоса в отдельный WAV и сохраните исходные записи и тайминг. При изменении событий пересоберите микс и обновите сцену из того же JSON. Отдельно держите читаемое состояние после акцента.

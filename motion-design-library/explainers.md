# Объясняющая 2D-анимация

Выбирайте приём по тому, что зритель должен понять за один просмотр. Для короткого эпизода достаточно одной мысли и одного последовательного маршрута внимания. Есть готовый рецепт прорисовки SVG-линий в [Shapes & 2D](shapes.md#20-single-line-draw).

## Схема процесса

1. Выделите начальное событие, следующий шаг и результат. Покажите развилку, если от неё зависит смысл. Разместите блоки в формате ролика вручную и привяжите концы связей к точкам на границах блоков.
2. Проведите акцент по активной связи с помощью `getTotalLength()` и `getPointAtLength()`. В момент прибытия выделите следующий блок. Остальные связи можно оставить видимыми приглушённо, чтобы зритель видел контекст. При общем сдвиге двигайте узлы и связи одной SVG-группой. Тогда форму и длину путей можно вычислить один раз. При движении узлов друг относительно друга пересчитывайте затронутые связи.
3. Оставьте итоговое состояние на экране для чтения. Короткий пример — сигнал идёт от источника через ретранслятор к приёмнику, затем появляется статус доставки.

## График по данным

Для сравнения используйте столбцы с общей нулевой базой и одинаковой шкалой. Для тренда используйте линию с подписанными периодами и единицами. Подписи и геометрию вычисляйте из одного набора утверждённых данных. При смене значений держите шкалу общей для сравниваемых состояний, плавно меняйте длину столбца или выделяйте точку на линии. Покажите точное итоговое значение и удержите его для чтения. Фактические показатели связывайте с источником, а демонстрационные данные явно обозначайте в кадре.

## Метки событий

Если несколько элементов реагируют на один момент, задайте ему имя и храните время в секундах в JS сцены, например `relayReceived` и `signalDelivered`. Из тех же значений берите начало движения и интервалы видимости элементов для Workbench. При озвучке расставляйте метки по ключевым фразам выбранной дорожки после монтажа пауз и сдвигов. Доступные интервалы расшифровки MotionLab описывают фрагменты записи. Точное попадание акцента во фразу требует прослушивания готовой дорожки с кадром.

## Анимация фрагмента кода

Для технического демо соберите два коротких состояния на HTML `<pre><code>` с подсветкой нужных строк. Сохраните положение общих строк, а изменившийся участок сдвиньте, замените или выделите в момент объяснения. Показывайте код как текст через `textContent` или HTML-экранирование. Для простого показа запроса и ответа подойдёт тот же приём.

## Проверка сцены

Вычисляйте каждый кадр через `window.__video.seek(t)`. Храните данные и тайминг в HTML или локальном скрипте рядом со сценой. Сохраняйте размеченные HTML/SVG-узлы в DOM с первого кадра и управляйте их видимостью в `seek(t)`. Workbench считывает структуру сцены при загрузке. Проверьте передачу акцента, читаемость финала и выбор узла в Workbench. Для проверки A → B → A дождитесь завершения `seek(t)` и отрисовки перед каждым снимком. Синхрон с голосом проверяйте в озвученном MP4.

Примеры Motion Canvas для справки — [вычисляемые точки линии](https://github.com/motion-canvas/motion-canvas/blob/main/packages/2d/src/lib/components/Line.ts#L81-L102), [именованные события](https://motioncanvas.io/docs/time-events/) и [изменения кода](https://motioncanvas.io/docs/code/#animating-code).
